# The AI reader: what a model may add to the registry, measured on two real pages

2026-10-05. Branch `registry/ai-reader`, stacked on `registry/param-rules`. L3 of the
change-intelligence plan.

`mendr read-page --provider <name> --url <page>` has a model read a provider's deprecation page and
return claims (id, shutdown date, replacements), each with a quote copied from the page. A
deterministic check then keeps only what the page literally supports. It is a dry run: it writes
nothing, and a reading never reaches the registry. Promotion stays the human gate it already is.

The model is a parser, never an authority. `discover` refuses to use one because "a hallucinated
model id would be indistinguishable from a real one". Here it is distinguishable mechanically: an
invented id has no sentence on the page to point to.

## The endpoint it was written for no longer exists

The first client targeted GitHub Models (free, `models: read` in Actions). GitHub's docs say GitHub
Models was fully retired on 2026-07-30, inference API included. Its host still answers **every**
request, an unauthenticated GET included, with HTTP 200 and the body `OK`. The earlier "verified,
HTTP 200 with the gh token" was that stub, not a model. A status code is not a verification.

So the client is now any OpenAI-compatible chat-completions endpoint, which most hosted providers
and local runtimes accept, chosen by whoever runs it:

| variable | meaning |
|---|---|
| `MENDR_READER_URL` | the chat-completions URL; https, or plain http only on this machine |
| `MENDR_READER_MODEL` (or `--model`) | the model id at that endpoint |
| `MENDR_READER_KEY` | sent as a bearer token when set |

A 200 that is not a chat completion is an error that says what came back
(`the endpoint answered, but not with a chat completion; it sent "OK\n"`). Nothing names a vendor.

## How it was measured with no endpoint configured

- **Reader:** a stand-in, not the production path. Claude Haiku 4.5, one isolated agent per reading,
  given exactly the system prompt and user message the CLI builds, allowed to read those two files
  and write its JSON answer and nothing else. Every answer then went through the shipped check
  against the same captured page.
- **Pages,** captured once through the shipped capture path:
  - Cohere, `docs.cohere.com/docs/deprecations`, `sha256:928b76168e7a`. It is served as Markdown to a
    non-browser client: 6,650 characters.
  - Groq, `console.groq.com/docs/deprecations`, `sha256:27486ecf2467`. It is HTML: 506,107
    characters, 19.5K after normalization.
- **Ground truth,** hand-read from the captures:
  - Cohere: 7 (id, date) pairs.
  - Groq: 40 pairs over 39 ids. Groq lists `deepseek-r1-distill-llama-70b-specdec` under two dates.
  - Not counted, by the page's own words. Cohere's 2025-09-15 list announces *deprecations*; the
    page's lifecycle says deprecated models stay available to existing users and get a shutdown date
    later. Its 2025-03-08 sunset is for models *fine-tuned with* `command-r-03-2024`, not the model.
- **Lies:** every kept claim was altered four ways. Each altered claim has to be refused, or have its
  invented replacement stripped:
  - the date moved one day;
  - the id lengthened;
  - one word dropped from the quote;
  - a replacement invented.

- 0 wrong replacements kept.

### Round 0: nothing false got through, and nothing true did either

Four causes, each confirmed against the answers:

1. **Groq writes table dates as `09/21/26`.** The date reader knew only ISO and "Month D, YYYY".
   All 78 Groq refusals were this, and every one of those quotes was on the page and named its id.
2. **Cohere writes "April 4th, 2026".** The ordinal was not read.
3. **Cohere's Markdown escapes the price as `\$1.00`.** The model quoted it as rendered, "$1.00".
4. **One reading compressed a list:** "...will be retired: embed-english-light-v2.0", skipping the
   items before it. That text is not on the page, and refusing it is correct.

One hole was found by construction before any model hit it. Flattened, a table reads as one run of
text, so a quote could start in one row and end in the next. "rerank-v3.5 2025-04-30
rerank-multilingual-v2.0" is contiguous on Cohere's page, and would have passed as a claim that the
**replacement** retires.

### What changed in the check

- **A table row, and the start of a section, is a line no quote can cross.** This covers HTML `<tr>`
  and headings, and Markdown pipe rows and headings. A quote carrying two rows itself is refused too.
  This lives in the normalizer that `check-rules` shares; its 8 live rule quotes still confirm.
- **Markdown escapes are read through.** The page's `\$1.00` reads "$1.00".
- **Dates:**
  - an ordinal day is read ("April 4th, 2026");
  - a numeric date is read only when one calendar reading exists. `09/21/26` is September 21;
    `10/08/25` could be October 8 or 10 August, so it states neither;
  - a day the calendar lacks is never a date.
- **The role rule.** In round 2, one reading claimed `Command-R-03-2024` shuts down 2025-03-08,
  quoting "we will sunset all models fine-tuned with Command-R-03-2024". The quote is on the page,
  names the id, and states the date. Only the meaning is wrong. Now an id that the quote names only
  right after a replacement or base-model phrase is not what the quote retires. The phrases are
  *fine-tuned with/from/on*, *in favor of*, *migrate to*, *replaced by/with*, *upgrade to*,
  *switch to*, *replacement*, and *successor*. Across all eight readings this removed that one claim
  and no other.

The prompt now says three more things:

- a dated sentence over a list is quoted with every item up to the model, none skipped;
- each table row is on its own line, and a quote never runs from one line into the next;
- a row whose numeric date reads two ways is quoted by its spelled-out heading instead.

### The recall that remains

Groq, 5 of 40 per reading, all refusals in the safe direction:

- rows whose date reads two ways where the model still quoted the row: `gemma2-9b-it` (10/08/25),
  `deepseek-r1-distill-llama-70b` (10/02/25), the two `llama3-groq-*-tool-use-preview` rows (1/6/25),
  and in one reading `meta-llama/llama-guard-4-12b` (03/05/26);
- in the other reading, the second date of the twice-listed specdec id was not returned.

## What the check guarantees, and what it does not

Each guarantee below has a test that fails when the guard is removed. All 24 guards were
mutation-checked, one at a time.

- The quote is on the page word for word, inside one table row or one section.
- It names the id as a whole token, and not only as a replacement or a base model.
- It states the date: ISO, written out (ordinals included), or numeric with a single reading.
- Every kept replacement is named in the quote. Anything else is dropped, never invented.

It does **not**:

- tell a deprecation date from a shutdown date in prose;
- read what a table header means;
- know that Groq's heading date is the shutdown date. That is Groq's convention, which the tables
  confirm, not a rule.

That is why a reading is a dry run.

The readings also surfaced three inconsistencies in Groq's own page, for a person to settle:

- `deepseek-r1-distill-llama-70b-specdec` is listed under 2025-03-24 **and** 2025-04-14.
- An "October 18, 2024" heading sits over a table dated 10/28/24.
- The `moonshotai/kimi-k2-instruct` row names `openai/gpt-oss-120b`, while the sentence above it
  names `moonshotai/kimi-k2-instruct-0905`.

## Where this would land, and what is undecided

- **The registry today** covers three providers: Google (39 entries), OpenAI (89) and Anthropic
  (39). The 47 Cohere and Groq pairs above would be new coverage. Every one of their dates has
  passed, so code calling those ids is failing now.
- **Not measured here:** whether the scanner sees Cohere and Groq call sites. Groq is commonly
  called through the OpenAI SDK with a different base URL.
- **Ajith's decision:** which endpoint, if any, runs the reader on a schedule. A $0 budget means a
  free tier, and GitHub Models just showed a free tier can disappear. Nothing in Mendr depends on
  the reader: `discover` and the human gate work without it.
