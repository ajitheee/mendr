the problem

your code keeps compiling until it doesn't

a provider retires a model id, or flips a param like max_tokens to max_completion_tokens on the newer models. nothing errors at build time. you find out when it 404s or 400s in production. mendr finds those spots and hands you the exact change.

the next wave is dated: openai retires gpt-4 and gpt-3.5-turbo on october 23, 2026. if either is still wired in anywhere, those calls start failing that day.

how it decides

it fixes the call, not every string that looks like one

accuracy over recall, everywhere. mendr only touches a model id it can prove is a live call, and only ships a fix that passes your own gates.

call-site aware

it swaps a model id only when that string is actually an argument to a recognized llm call. an id sitting in a pricing table, a model-picker array, or a lookup map is left alone.

model-coupled params

for a param fix it traces the model at each call site and only removes or renames the param when that model needs it. a claude-opus call can lose temperature while a sibling haiku call keeps it.

verified, not guessed

replacements carry a per-entry verdict checked against the live public model catalogs. only a verified entry is ever auto-applied — if it isn't verified, mendr locates the spot and refuses rather than risk a bad patch.

gated before it's trusted

a fix earns Tier A only after the patched code type-checks and your tests pass. anything that fails the gate is shown for review, never quietly applied.

new · the dependency audit

see what a retired model still costs you

not every model id lives at a call site — some live in config, a database, a feature flag, or only in the runtime request. two read-only commands close that gap. everything runs in your own environment; no source and no keys ever leave it.

measure

usage-audit

reads your provider's own usage api with a read-only key you set in your own shell, and reports which deprecated models are actually taking traffic and dollars, with deadlines. it measures exposure; it doesn't read a single prompt.

locate

config-scan

finds deprecated ids across config and iac (yaml, json, .env, helm) and tells a live selector like model: gpt-4 from a catalog definition. on dify's 3,845 config files it cut false "change this" hits from 148 to 0.

why a diff, not a pull request

small enough to read in a few seconds

i don't trust a tool that rewrites my code without showing me first, and you shouldn't either. mendr prints a patch to stdout. read it, and if it's right apply it with --write or pipe it straight into git apply. there's also a github action if you want it to open the reviewed pull request for you in CI.

▚ .github/workflows/mendr.yml
name: mendr
on:
  schedule: [{ cron: "0 8 * * 1" }]
jobs:
  llm-deprecations:
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write }
    steps:
      - uses: actions/checkout@v4
      - uses: ajitheee/mendr/mendr-action@v1
"

i run chefcode, an invoice tool for restaurants, and one day it just stopped reading invoices. google had retired gemini-2.0-flash and my calls pointed at a dead id. later i pointed mendr at that same repo before my fix, and it produced the exact change i'd already made by hand. that was the whole reason to keep building it.

the commands

a handful, and you'll mostly use one

mendr fix-llm <path>

scan a repo for retired model ids and coupled params, print the gated diff. the one you'll use.

mendr watch [path]

track the deprecated ids a repo touches; --install scaffolds a github action that keeps one self-updating issue current.

mendr usage-audit [provider] · alpha

read-only: which deprecated models actually consume requests and money, with deadlines.

mendr config-scan [path] · alpha

locate deprecated ids in config and iac, separating live selectors from catalog data.

where it's at, honestly

early, and not pretending otherwise

it's new and doesn't have paying users yet. it's me, and the one production breakage that made me build it.
the suite is at 664 passing tests, run across 26 real public repos with 0 wrong edits — the gate blocks anything it can't verify.
the config scan was hardened on dify's 3,845 config files: false "change this" selectors went from 148 to 0.
typescript, tsx, and python. a pure-js repo gets told nothing analyzable was found, not a false all-clear.
it reads inline model strings and one-hop consts. an id built from an env var or string concat is skipped on purpose.
coverage today is openai, anthropic and google, plus config files and stripe renames. if you run it and it does something dumb, that's the feedback worth sending.
