The problem

A retirement date arrives, and nobody knows what breaks.

A provider retires a model and teams scramble: grep every repo, guess what's live, risk a global find-and-replace. Mendr turns that firefight into a measured, evidence-based migration.

Before Mendr
  • Provider retirement announcement
  • Search every repository manually
  • Unknown production usage
  • Unsafe global replacement
  • Surprise firefighting
With Mendr
  • Exposure identified early
  • Relevant files located
  • Requests and cost measured
  • Evidence-based decision
  • Controlled migration

How it works

Two signals, joined into one decision.

Usage data shows what is live. A config scan shows where it lives. Mendr joins them so a migration rests on evidence, not a guess.

Migration decision

Neither source is enough alone. Usage data tells Mendr what is live. Repository scanning tells Mendr where a possible change lives. The decision comes from joining them.

The product

Real command output. No mock dashboard.

Mendr is a CLI and a GitHub workflow. Here is what it actually prints — three commands, muted and legible.

usage-audit

Which deprecated models still burn requests and dollars.

Trust & control

You stay in control the whole way.

Mendr runs where your code already runs, changes nothing on its own, and stops at anything it can't prove.

Runs inside your GitHub Actions
Default branch remains untouched
Never auto-merges
Uncertain findings need human review
Metadata only. Mendr reads dependency metadata. It does not need prompts, responses or customer records.
Keys are read-only, and handled by you. The usage audit needs a read-only usage key set in your own shell. A provider Admin key is powerful — treat it accordingly; Mendr never asks you to send it.
