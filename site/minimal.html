deprecation fixer for llm code

a small cli that finds deprecated llm model ids and the params that die with them, then hands you the exact diff. it never touches your files on its own. you read the patch, you decide.

01/

the problem

your code keeps compiling until it doesn't

a provider retires a model id, or flips a param like max_tokens to max_completion_tokens on the newer models. nothing errors at build time. you find out when it 404s or 400s in production. mendr finds those spots and hands you the exact change.

the next wave is dated: openai retires gpt-4 and gpt-3.5-turbo on october 23, 2026. if either is still wired in anywhere, those calls start failing that day.

02/

how it decides

it fixes the call, not every string that looks like one

a /

only a real call gets touched

it swaps a model id only when that string is actually an argument to a recognized llm call. an id sitting in a pricing table, a model-picker array, or a lookup map is left alone.

b /

the right param at the right site

for a param fix it traces the model at each call site and only removes or renames the param when that model needs it. a claude-opus call can lose temperature while a sibling haiku call keeps it.

c /

a dated registry backs every swap

replacements carry a per-entry verdict checked against the live public model catalogs. only a verified entry is ever auto-applied. if a replacement isn't verified, mendr locates the spot and refuses, rather than risk a bad patch.

d /

tier a means the gates passed

a fix earns tier a only after the patched code type-checks and your tests pass. anything that fails the gate is shown for review, never quietly applied.

03/

new · the dependency audit

see what a retired model still costs you experimental · v0.2.0-alpha

not every model id lives at a call site. some live in config, a database, a feature flag, or only in the runtime request, where the code scan finds nothing. two read-only commands close that gap. everything runs in your own environment. no source and no keys ever leave it.

measure

usage-audit

reads your provider's own usage api with a read-only key you set in your own shell, and reports which deprecated models are actually taking traffic and dollars, with deadlines. it measures exposure; it doesn't read a single prompt.

locate

config-scan

finds deprecated ids across config and iac (yaml, json, .env, helm) and separates a live selector like model: gpt-4, the place to change, from a catalog definition, which is data and left alone. on dify's 3,845 config files it cut false "change this" hits from 148 to 0.

04/

why a diff, not a pull request

the change is small enough to read in a few seconds

i don't trust a tool that rewrites my code without showing me first, and you shouldn't either. mendr prints a patch to stdout. you read it, and if it's right you apply it, either with --write or by piping the diff straight into git apply. there's also a github action if you want it to open the reviewed pull request for you in CI.

1const MODEL_NAME = 2- "gemini-2.0-flash" 3+ "gemini-flash-latest"

verified before it touches your code — type-check and tests pass, replacement checked against the live catalog.

05/

where this came from

this started because a model retirement broke my own app. i run chefcode, an invoice tool for restaurants, and one day it just stopped reading invoices. google had retired gemini-2.0-flash and my calls were pointing at a dead id. i tracked it down and fixed it by hand, swapped the model id, checked the params still made sense, shipped it.

later i pointed mendr at that same repo before my fix, and it produced the same change i'd already made by hand. that was the whole reason to keep building it. not a demo repo, my actual production breakage, fixed the same way.

06/

the commands

a handful, and you'll mostly use one

mendr fix-llm <path>scan a repo for retired model ids and coupled params, print the gated diff
mendr watch [path]track the deprecated ids a repo touches; --install scaffolds a github action that keeps one self-updating issue current
mendr usage-audit [provider] · alpharead-only: which deprecated models actually consume requests and money, with deadlines
mendr config-scan [path] · alphalocate deprecated ids in config and iac, separating live selectors from catalog data
mendr verify-registrycheck every replacement against the live public model catalogs
07/

run it in CI

one workflow file, a verified PR when something retires

drop this into .github/workflows/mendr.yml. it runs in your own CI, gated on your tests, and opens one pull request you review.

name: mendr
on:
  schedule: [{ cron: "0 8 * * 1" }]
  workflow_dispatch: {}
jobs:
  llm-deprecations:
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write }
    steps:
      - uses: actions/checkout@v4
      - uses: ajitheee/mendr/mendr-action@v1
08/

where it's at, honestly

early, and not pretending otherwise

  • it's new and doesn't have paying users yet. it's me, and the one production breakage that made me build it.
  • the suite is at 664 passing tests. i ran fix-llm across 26 real public repos with 0 wrong edits, because the gate blocks anything it can't verify.
  • the config scan was hardened on dify's 3,845 config files: false "change this" selectors went from 148 to 0 once it learned to tell a live selector from a model catalog.
  • typescript, tsx, and python. a pure-js repo gets told nothing analyzable was found, not a false all-clear.
  • it reads inline model strings and one-hop consts. an id built from an env var or string concat is skipped on purpose.
  • coverage today is openai, anthropic and google model ids and coupled params, plus config files and stripe renames. more is coming.
  • if you run it and it does something dumb, that's exactly the feedback worth sending.
