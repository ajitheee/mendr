Security

The short version. The full, code-level detail — data-flow diagram, threat model, permissions, encryption, retention, audit log, incident response — is in TRUST.md.

What runs where

The scanner runs inside your GitHub Actions, on your runner. Mendr's hosted App never clones or reads your code — it holds checks: write and metadata: read only, and receives just the findings your CI chooses to send.

Enforced in code, not just promised

  • Nothing uploaded by default. The audit makes no network calls; a build-time test runs it under a preload that makes every network primitive throw, and it must still pass. Run it yourself with --offline.
  • Secrets redacted. Everything that could leave — the tracking-issue body and every stored snippet — passes through the same secret redaction, tested on every build.
  • No stored credentials. No GitHub tokens or provider keys are stored; findings are encrypted at rest with a key kept outside the database. A code test fails if a credential-shaped column is ever added.
  • Least privilege. The scaffolded workflow asks for contents: read + issues: write; the App asks for checks: write + metadata: read. Nothing modifies your default branch; nothing merges.

Your data, your control

Uninstalling the App, removing a repository, or clicking "Delete stored data" removes your findings. Retention can age them out automatically. See Privacy.

Supported versions

Only the newest tagged release receives fixes; a fix ships as the next tag, never a moved one. See the changelog.

Reporting a vulnerability

Use GitHub's private vulnerability reporting: github.com/ajitheee/mendr/security/advisories/new. Expect acknowledgement within three business days and a fix as a new tag with the advisory named in the changelog. Full policy and safe-harbour terms: SECURITY.md. How we handle a confirmed incident: INCIDENT-RESPONSE.md.
